# ADR-001: Стор обновляется ответом сервера, а не перезагрузкой

## Статус
Принято — 2026-10-06

## Контекст
После любого сохранения интерфейс перезагружал весь список людей, все связи и профиль
(6+ запросов), на время загрузки заменял профиль спиннером — вкладка сбрасывалась, а часть
окон вызывала несуществующий `refreshCurrent()`.

## Решение
- Сервер — источник правды, но стор меняется **его ответом**: созданная/изменённая запись
  вставляется или заменяется по `id`, удалённая убирается.
- Удаление оптимистичное: запись исчезает сразу и возвращается, если сервер отказал.
- Связи в профиле — производный вид (`direction`, `person_name`), поэтому после изменения
  перечитывается только список связей открытого человека.
- Ответ на устаревший запрос профиля (уже выбран другой человек) отбрасывается.
- Спиннер — только при переходе к другому человеку.

## Отвергнуто
- **Перезагрузка после каждого действия** — то, что было: медленно, мигает, сбрасывает вкладку.
- **Оптимистичное создание/изменение** — нужен временный id и согласование с сервером;
  ответ локального API приходит за десятки миллисекунд, выигрыш не стоит сложности.

## Последствия
Все изменения данных идут через действия `usePersonStore` / `useTreeStore`; модалки не
вызывают API напрямую для записи. Тесты — `frontend/tests/stores.test.ts`.
