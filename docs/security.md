# Безопасность

Приложение хранит чувствительные персональные данные (медицина, документы, аккаунты). Ниже — известные
риски на 2026-10-06 и что с ними делать. Пункты отмечены по важности.

## Требует действий

| Важность | Риск | Что сделать |
|---|---|---|
| Критично | Токен Telegram-бота был записан в `bot.py`/`run_bot.py` и опубликован в истории этого **публичного** репозитория | Отозвать в @BotFather (`/revoke`), новый токен — только в `.env`. Код теперь читает `BOT_TOKEN` из окружения |
| Высоко | `digital_accounts.password`, `backup_codes`, `security_questions` хранятся открытым текстом | Шифровать на сервере (ключ из `.env`, например Fernet из `cryptography`, уже в зависимостях); миграция существующих строк — с резервной копией |
| Высоко | API (8000), MySQL (3306) и phpMyAdmin с автологином (8081) слушают `0.0.0.0` — доступны всей локальной сети | Публиковать порты только на `127.0.0.1` (`"127.0.0.1:8000:8000"`), phpMyAdmin — убрать или без автологина |
| Средне | Нет авторизации; CORS `*` | Добавить вход (хотя бы один пароль/токен) и ограничить CORS адресом интерфейса |

## Уже сделано

- 2026-10-06: пароли MySQL (`jade_user`, `root`), попавшие в историю репозитория, заменены на случайные;
  новые значения — только в `.env`.
- Секреты убраны из кода и `docker-compose.yml`: значения в `.env` (в git не попадает), шаблон — `.env.example`.
- Список людей (`/api/persons`) больше не отдаёт пароли и коды аккаунтов всех людей.
- Ошибки сервера не показывают в браузере текст SQL и адрес базы.
- Тесты не могут запуститься на рабочей базе (`jade_archive`).
- `backend/.dockerignore` не пускает в образ `.env`, дампы, тесты и локальное окружение.

## Правила

- Никогда не коммитьте `.env`, дампы (`*.sql`) и резервные копии — они в `.gitignore`.
- Перед пушем проверяйте diff на секреты: `git diff --cached | grep -iE "password|token|secret"`.
- Попавший в публичный репозиторий секрет считается скомпрометированным — сначала отзовите/смените,
  затем, при желании, чистите историю.
