# План: рабочие API и реактивный CRUD (A.R.K.)

## Цель
Все API, которые вызывает интерфейс, работают; после создания, изменения и удаления
интерфейс обновляется сразу, без перезагрузки страницы, без мигания профиля и без потери
открытой вкладки.

## Допущения
1. «Улучшить интерфейс» = реактивность и исправление сломанных состояний, не редизайн.
2. Источник правды — сервер: стор обновляется ответом API (созданная/обновлённая запись),
   а не повторной загрузкой всего.
3. Боевая база не трогается: тесты идут на отдельном MySQL в Docker.
4. Схема БД не меняется (нет миграций данных).

## Задачи
### Фаза 0 — безопасность работы
- [x] Ветка `fix/api-reactive-crud`, снимок текущего состояния без секретов и дампов
- [x] Тестовый MySQL в Docker (порт 3307, tmpfs), pytest + TestClient

### Фаза 1 — бэкенд (TDD)
- [x] Тест-контракт: каждый ресурс list/get/create/update/delete + 404 (сначала красный на B1, B2)
- [x] B1: `GET /persons/{id}/social`
- [x] B2/B3: одна реализация категорий, `/tree` до `/{id}`; убрать дубли medical
- [x] B4: лимит списка по умолчанию 1000 (максимум 1000)
- [x] B5: лёгкая схема для списка (без аккаунтов и вложенных коллекций) — только если интерфейс не использует эти поля
- [x] B6: убрать неработающий alembic из старта
- [x] Контрольная точка: все тесты зелёные
