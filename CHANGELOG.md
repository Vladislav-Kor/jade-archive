# Changelog

## [3.1.0] - 2026-10-06
### Security
- Токен Telegram-бота и пароли MySQL убраны из кода и `docker-compose.yml` — теперь только в `.env`
  (шаблон `.env.example`). Токен, попавший в историю публичного репозитория, нужно отозвать.

### Added
- CI/CD в GitHub Actions: тесты бэкенда на MySQL 8, тесты и сборка фронтенда, сборка образа;
  на `master` — публикация образа бэкенда в GHCR.
- Документация: `docs/` (архитектура, API, модель данных, бэкенд, фронтенд, разработка, развёртывание,
  безопасность) и обновлённый README.

### Fixed
- Вкладки «Недвижимость», «Транспорт», «Дела», «Медицина», «Соцсети» всегда были пустыми: стор их не загружал.
- Соцсети не грузились (`GET /persons/{id}/social` отсутствовал, 405); редактирование ссылки удаляло и создавало её заново — при сбое ссылка терялась (теперь `PUT /social/{id}`).
- После сохранения в любой модалке — ошибка «refreshCurrent is not a function», окно не закрывалось, хотя данные сохранялись.
- Редактирование дел и медицинских записей не открывалось (`getById` не существовал).
- Vite загружал устаревшие `.js` вместо `.ts`; испорченные URL в `categories`, `real-estate`, `vehicles`; кодировка cp1251 в `client.ts`.
- Очищенное при редактировании поле не стиралось на сервере.
- Уведомления никто не показывал — добавлен вывод уведомлений.
- `init_db()` не создавал таблиц (два разных `Base`) — на чистой установке приложение не работало.
- `/categories/tree` недостижим (422); дубли маршрутов medical и categories.
- Список `/persons` отдавал пароли и коды аккаунтов всех людей и обрезался на 100 записях.
- Ошибки сервера показывали в браузере текст SQL-ошибок и адрес базы.
- Двойное нажатие «Сохранить» создавало дубликаты.

### Changed
- Интерфейс обновляется сразу после создания, изменения и удаления — без перезагрузки и без потери открытой вкладки; удаление мгновенное с откатом при ошибке.
- Контейнер бэкенда стартует без падающего `alembic`, без лишних системных пакетов.

### Added
- 27 тестов API (отдельный MySQL) и 19 тестов фронтенда (vitest).
